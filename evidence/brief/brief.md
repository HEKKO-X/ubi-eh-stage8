# Ethical Hacking Advanced 4: Break and Repair the Directory Control Plane

## Window and scoring

Use the exact opening and deadline shown in the authenticated stage room. No
revision. Recorded defense. 100 points: release integrity and scope 10,
directory ingestion and effective-rights model 20, path discovery and direct
validation 25, reliable automation and cleanup 20, detection and remediation
15, defense 10.

## Controlling execution route

The issued offline directory range is the complete scored target. It requires
Python 3.11 or newer, 4 GB RAM, 2 GB free disk, and no VM, hypervisor, Docker,
cloud account, live Active Directory domain, or internet access after setup.
Generate only your assigned D-set using the candidate JSON downloaded from your
stage room. Never substitute `variant.example.json` or another candidate's file.

GOAD-Light is now an optional compatibility route. Candidates who already
provisioned it may retain their health, enumeration, path, detection, and
remediation evidence, but must export decisions through the same portable graph
and test interfaces. There is no hardware bonus and no requirement to restart.

## Required work

1. Verify the archive, candidate JSON, generated range, and marker bindings.
2. Parse users, groups, computers, SPNs, sessions, group membership, ACLs,
   delegation, and object state into a versioned graph without embedding SIDs,
   names, path IDs, flags, or expected answers.
3. Validate at least eight graph edges from primary directory or event records.
   Reject the planted stale edge and explain the failed precondition.
4. Discover two independent paths from the supplied foothold to the two private
   proof objects. At least one path must combine credential abuse with an ACL or
   delegation edge.
5. Implement one path as candidate-authored automation. It must resolve dynamic
   identifiers, succeed three of three times from a clean generated state, obey
   the proof limit, and remove all temporary objects and state.
6. Write two event-sequence detections for decisive path edges with positive and
   benign controls.
7. Remediate both paths at their root causes. The two attack tests must fail at
   the intended edges while health, legitimate access, and unrelated graph
   assertions remain green.

## Required proof

- Generated-range manifest, candidate binding, health report, and source hashes.
- Versioned graph schema and direct evidence for eight or more accepted edges.
- Stale-edge rejection with the exact failed precondition.
- Two path graphs, raw evidence locators, and proof-limit accounting.
- Three clean automation transcripts and machine-readable cleanup results.
- Before/after remediation graph diff and negative path tests.
- Two detection rules with positive and benign replay results.
- Recorded clean-state reproduction of one staff-selected edge.

## Safety and compatibility

The supplied offline range is the only mandatory target. Do not test production,
employer, school, public, or shared directory services. Existing GOAD evidence
is accepted only from a candidate-owned isolated range and only within the same
scope, cleanup, evidence, and remediation contract.

## Mission interface and handoff

- **You receive:** an offline range generator, candidate JSON, supplied
  foothold, private proof bindings, event replay, and public tests.
- **You build:** effective-rights graphing, direct edge validation, two attack
  paths, reliable automation, cleanup, detections, and remediations.
- **You prove:** identifiers are resolved at runtime and both paths fail at the
  intended edges after remediation.
- **You hand forward:** reusable identity-graph code, edge evidence, detections,
  cleanup, and remediation records for Stage 9.
