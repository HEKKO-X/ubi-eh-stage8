# Portfolio Continuity Record

## Previous-stage commit and component reused

Previous stage: Stage 7 - "Own the Cloud" (AWS IAM privilege escalation).
Previous-stage commit: 1522ac3993eca282efb2e4cbe5bc2293b0207393
(repository: local, not pushed to GitHub for that stage)

Stage 7's own continuity-record.md explicitly named four things to hand
forward into this stage. This record honestly tracks how each was used:

1. **Identity-path graph model** (principal_before/principal_after
   tracking in Stage 7's attack-path.json) - REUSED. This is the direct
   ancestor of enumeration/discover.py's graph/edge model in this stage:
   objects, relations, a foothold, and a walk from foothold to target,
   just generalized from AWS IAM principals to AD-style objects/edges.

2. **CloudTrail event-provenance linking pattern** (cloudtrail_event_id
   per step) - ADAPTED, not reused directly. This range has no CloudTrail
   equivalent; events.jsonl plus SHA-256 hashing of every output file
   (evidence/all-artifact-hashes.txt) serves the same provenance-linking
   purpose in this stage's context.

3. **Teardown/residual-check discipline** - PARTIALLY CARRIED FORWARD.
   This stage's cleanup operation (via range_client.py) resets temporary
   flags after each automation run, and remediation/remediation_test.py
   confirms range health stays green post-remediation. A full residual
   check equivalent to Stage 7's residual-checks.json was not built,
   since the portable range has no persistent cloud resources to check
   for leftover state - this is a genuine simplification, not a
   like-for-like continuation, and is noted honestly here.

4. **Honest disclosure model for deviations** - REUSED. Applied twice in
   this stage: (a) a missing B2-specific manifest_signature was left
   marked as an open gap rather than reusing the stale B1 signature or
   fabricating a value, and later resolved once the real value was found
   on the dashboard; (b) a git history mistake (candidate.json committed
   despite an intended .gitignore) was disclosed and corrected by
   deleting and rebuilding history, rather than silently patching over it.

## Interface consumed and backward-compatible extension

Stage 7's evidence-logging convention (timestamped log entries via
`tee -a`, one command = one logged evidence block, claim registry in
evidence-index.csv) was extended without modification to this stage's
Python-based portable range - only the underlying commands changed
(portable_range.py act/build/health instead of aws-cli/terraform).

## Provenance preservation evidence

All raw command outputs in this stage are preserved via `tee` into
evidence/*.txt and per-phase run logs (automation/path1-run-log.json,
etc.), each independently SHA-256 hashed in evidence/all-artifact-hashes.txt
and evidence/documentation-hashes.txt - the same raw-to-result discipline
used in Stage 7's setup-evidence.log.

## Migration record

One incompatible change: Stage 7 used real AWS CloudTrail as an
independent, tamper-evident event source. This stage's events.jsonl is
generated by the same tool being tested, and is reset on every
`build --force` call (see known_limitations in assessment-manifest.json).
This is a weaker provenance guarantee than CloudTrail, and is disclosed
here rather than presented as equivalent.
